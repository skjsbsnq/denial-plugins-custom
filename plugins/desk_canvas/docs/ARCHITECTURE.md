# Desk Canvas 实现说明

## 桌面层与输入

`DeskCanvasPlugin` 贡献 `ShellSurfaceLayer.desktop`，只在主显示器非空工作区挂载。锁屏、概览和壁纸选择期间隐藏；不预留任务栏工作区。每屏同时显示全部桌面内容会造成重复，因此当前选用主屏统一显示，主屏变化由宿主卸载旧实例、挂载新实例，持久化网格重新适配可用尺寸。

宿主已经将原生窗口内容、弹出层和系统层区域从桌面输入中扣除。桌面 `GestureDetector` 沿用该路由；永久注册全桌面 `ShellInputRegion` 会把这些扣除区域重新加回，因此明确不这样做。菜单和确认框使用 `ShellPopupController`，临时获得输入并在退出时隔离点击、恢复焦点；隐藏或卸载桌面时关闭弹层。异步确认有代次标记，旧操作回包不得清除新对话框。

弹层显式使用 `barrierColor: Colors.transparent` 和 `ShellDismissPolicy.none`：桌面右键菜单不得压暗壁纸，关闭行为由弹层内的全屏关闭层负责。该层位于菜单之下，因此再次右键会直接移动菜单，点按空白处或 Esc（`CallbackShortcuts`）关闭。连续右键时先 `completeClose` 仍在退出的旧弹层，避免旧层退出动画结束后把焦点抢回桌面。菜单使用紧凑的 30 px 行、分组分隔线和三档图标大小，行内文字由宿主文字主题派生。

弹层的 `transitionDuration` 为 `Duration.zero`。托管弹层用 `FadeTransition` 做淡入，透明度小于 1 时会插入 `Opacity` 层；`BackdropFilter` 在该层内取不到身后的场景，于是先显示为半透明、等淡入结束才突然出现模糊。零时长让首帧就是完全不透明，`RenderOpacity` 直接绘制子节点，背景模糊一次到位；Windows 10 的右键菜单本来也没有过渡动画。关闭同样即时，避免退出中的菜单继续接收点击。

## 数据与生命周期

`DesktopStore` 为纯 Dart 状态和 I/O 层，环境与 `FileActions` 可注入。目录来自 XDG 配置，缺项回退 `$HOME/Desktop`；显式 HOME 禁用与无效内容产生错误。初始化先校验 HOME 与配置根为绝对路径，失败时不读取布局、不注册监听。解析为数据，拒绝命令替换和 NUL；user-dirs 限制 64 KiB、桌面入口 256 KiB、布局 1 MiB、列表 10000 个项目。读取使用固定上限文件句柄，避免只先 stat 再无限读取的竞态。

订阅目录后执行扫描。事件合并 120 ms，刷新串行，配置 watcher 在解析前建立，确保损坏配置修复后自动恢复。桌面不存在时监听最近现存祖先，收到目标路径重建事件后重新订阅。父目录的不相关事件不会触发桌面重扫。卸载取消事件与定时器，等待中的扫描通过代次和 disposed 标记失效；不创建第二套宿主服务或周期轮询。

XDG 配置变化后不继续显示旧目录；旧项目在打开、删除和重命名前校验当前列表与桌面归属。损坏的单个入口和失效链接保留可见错误，不导致整个列表加载失败。系统文件操作失败在 UI 报告；监听异常提示手动刷新。

## 入口、图标与文件操作

`.desktop` 仅读取 `[Desktop Entry]`，本地化 Name 优先完整地区再语言，应用动作不会覆盖主名称。应用入口须为 `Type=Application` 且有 Exec 或 D-Bus 激活。显示名称由 `displayName` 统一产生：有可用 Name 时使用它；没有时去掉 `.desktop` 后缀，与 Windows 隐藏实现后缀的行为一致。普通文件和目录保持原文件名；以 `.desktop` 结尾的文件夹仍是文件夹。

`desktop_sdk_adapter.dart` 在 isolate 使用公开 `DesktopAppsRepository.resolveIconPath`，解析结果按图标名在进程内长期缓存，新名称串行成批处理，不再每次目录事件新建一个冷缓存 isolate。已安装应用目录只在打开快捷方式时按需读取一次，并在桌面项目变化后失效；本轮不再读取 SDK `homeGridControllerProvider`，因为该非 autoDispose 控制器会为剩余会话保留应用目录 watcher、周期重扫和完整应用列表。插件仍不创建额外轮询。桌面副本仅在原文件名与有界读取内容完全一致时使用宿主启动，尊重 opaque 应用身份。特殊激活与外部入口集中委托 `GioFileActions`，不执行 shell 或自行解析 Exec。

新建目录使用真实桌面路径；重命名经 `renameat2` 的 no-replace 标志，不把 exists 检查当作防覆盖保证。移动图标仅写布局 JSON，文件不移动。删除需要确认并使用 `gio trash`；不能移入回收站时报告失败，不退化为永久删除。外部 `.desktop` 运行需每次确认，不能把来自 App Shelf 以外的任意文件默认视为可信程序。

## 排布、持久化与扩展边界

网格列优先排列，合法保存位置优先，重复和越界坐标分配空位。多选拖动以选中组移动，逐个解决目标冲突；尺寸变更重新适配。溢出列可水平滚动，框选和菜单做滚动坐标换算，键盘移动同步滚动位置。布局按文件名保存，重命名显式继承位置；隐藏项目坐标保留。

App Shelf 与此插件通过真实 `.desktop` 文件及目录事件协作，不相互依赖、不创建专用消息通道。后续原生拖放、文件剪贴板与多屏文件分配需要独立设计和 SDK 能力确认。

无界面测试用临时目录、假打开和回收站后端；真实 Linux no-replace 后端只测试临时文件。根集成检查验证 App Shelf 精确写入后自动出现在目录状态中、重复和冲突、目录变更恢复及重命名原子防覆盖。候选编译与用户桌面视觉检查分别执行，不能互相替代。

## 本次交互与开销修正

`DesktopHighlight` 在项目内部维护悬停，只对背景做短过渡；选中描边从内容布局中移出，避免 `Container` 计算边框内边距造成 1 px 偏移。静态前景按项目、图标路径、宿主主题与图标尺寸缓存，并置于绘制边界中。按下主键立即选择，双击打开仍交给手势识别器；微小拖动回到原格时不重写布局。背景反馈尊重宿主动画时长倍率及 `MediaQuery.disableAnimations`，不使用缩放。

布局有 dirty 标记，只在目录数据、尺寸、图标档位或排布变化时更新；不因悬停、选择或提示变化而重复 `arrange`。空位分配游标只前进，避免对每个新图标从第一个格子重新扫描。水平溢出时仅构建可见范围和相邻一列，滚动局部构建不涉及布局与弹层拥有者。桌面取消整份应用目录订阅，启动时仍按需读取公开状态。尚未测量桌面实际帧率。

新增纯 Dart 大规模溢出排布检查与控件悬停/反向/固定前景位置检查；后者在当前缺少 `flutter_tester` 的套件上无法加载，必须在具备匹配测试引擎的环境执行。

## 保持视觉参数的第二轮优化

背景过渡改为 `HighlightDecoration`，继承 Flutter 原有隐式动画状态与 `DecorationTween`，沿用原装饰画笔、颜色、曲线和时长；每帧只通知 `CustomPainter` 重绘。外层绘制边界覆盖背景与前景，避免背景 tick 向整桌面传播，内层保留静态前景。拖动通过 SDK 公开 `RetainedTranslation` 接收 `ValueNotifier<Offset>`，逐帧只动绘制变换及命中坐标，开始／结束仍由画布管理；不设置额外像素取整或采样，保持原连续位移。拖动项无论是否出视口均保持挂载，避免卸载手势识别器。

`DesktopViewportIndex` 在布局更新时建立列到项目索引的映射。滚动仅访问相邻列，再恢复原项目叠放顺序，不扫描全部目录；回归对比原全扫描的精确可见集合及顺序。`reuseDesktopItems` 在真实扫描完成后按路径和完整入口字段、名称、目录类型、错误复用对象；全部对象与次序相同时保留列表身份。它不省略文件校验，字段或路径变化立即失效，目录错误仍照常更新。列表身份不变时不重新排布或丢弃前景缓存；Material 主题转换按不可变宿主主题身份缓存。

## 独立审查：交互结束与后台开销

选择与 hover 不再无期限跟随上次右键或打开：操作结束调用 `resetFeedback`，清选择、框选及拖动状态并递增反馈代次。`DesktopHoverFeedback` 清理后要求真实 `PointerHoverEvent` 移动；`PointerEnterEvent` 即使含非零 delta 也不能解除抑制，因为 MouseTracker 可能从旧事件合成它。正常初次进入及新鼠标运动仍有原强调色反馈。窗口投影仅监听 active ID 的变化，回调在帧后执行并检查交互代次及当前窗口，避免覆盖新的用户操作。

菜单只保留并收尾本插件的 popup ID；外部关闭后的迟到回调同时检查反馈代次、对话框代次和旧位置。运行入口前立即关闭自身弹层并释放焦点，外部入口确认成功后不再把焦点强行还给桌面。`DesktopCanvas.createStore` 是无界面控件测试的可选依赖注入，正式入口不传该参数，仍创建真实 `DesktopStore`。

选择框由 ValueNotifier + CustomPainter 绘制，指针帧只在选择集合变化时触发画布更新；候选先按列索引过滤。`moveDesktopItems` 使用 Set 与单向空位游标，纯 Dart 随机对照验证与原策略一致。`DesktopRefreshQueue` 将扫描中新增请求统一并入下一轮，各调用在覆盖其请求的扫描后完成；错误不污染后续请求，卸载取消尚未开始的请求。监听取消先快照、清原列表，再 await，避免刷新与卸载同时迭代造成异常。

新增临时目录队列回归与假存储/假服务控件回归。匹配套件仍没有 `flutter_tester`，控件断言尚未执行；静态分析、算法与文件回归不能替代桌面视觉和帧率验证。

## 第三轮：失效范围与常驻开销

宿主挂载 surface 时只包了 `ClipRect`，没有绘制边界，所以图标层的任何一次重绘都会冒泡到整帧场景（含壁纸）。入口现在在最外层包一层 `RepaintBoundary`，把桌面自身的重绘限制在工作区内。全屏窗口覆盖工作区时，桌面层不再保持可见合成，只有概览或“显示桌面”需要时才绘制。

托管菜单的重建曾由画布的每次 `setState` 触发：拖动、框选、选择变化都会重新创建 `BackdropFilter` 与抗锯齿裁剪。现在只有菜单实际绘制的内容（目标项、选择数量、位置、标题、提示、忙碌状态、图标档位与隐藏项开关）变化时才递增重建版本，其余更新不再触碰这层滤镜。

`changed()` 在列表身份、错误与加载状态都未变化时直接返回，避免一次无差异的目录重扫重建全部图标控件。图标名解析结果在进程内缓存并串行成批，不再为每批新名称新建冷缓存 isolate；已安装应用目录改为打开快捷方式时按需在 isolate 读取一次，桌面项目变化后失效。

`HighlightPainter` 复用同一个插值动画实例，并按当前装饰值比较是否需要重绘；此前每次重建都会被视为新画笔而重画装饰。上述改动只调整失效范围与缓存，不改变材质、阴影、字体、圆角、图标档位和动画参数。真实帧率与显存占用未在本机测量。
